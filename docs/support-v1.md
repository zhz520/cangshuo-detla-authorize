# 在线客服首版

本模块和授权运营中心共用 Node 进程、现有 SQLite 和构建产物。公开客服页面采用 AI-CS 的蓝白聊天布局思路，使用本仓库的 Vue 组件实现。访客和客服仍然进行人工对话；可选的外部模型只用于后台内容审核。

## 开通

1. 在授权运营中心确认客户已登记且处于启用状态。
2. 进入「在线客服 → 客服站点」，新增站点，设置客服账号、独立密码和公开的 HTTPS 隐私说明链接。新建表单默认不开放；确认和客户约定审核范围、数据保留周期及处置方式之后再开放。
3. 访客入口为 `/chat/<站点编号>`；客户客服入口为 `/chat/<站点编号>/agent`。原授权后台首页仍为 `/`。如使用独立客服域名，可在反代将该域名的 `/` 重定向至相应访客入口。
4. 访客不用登录。发第一条文字或上传第一份附件时建立独立会话。访客凭浏览器 Cookie 在 30 天内恢复原会话；客服账号只可接待自己站点。第一版一个站点配置一个客服账号。重设密码或停用站点会让该站点的现有客服登录失效。
5. 支持 PNG、JPEG、WebP 和 PDF，每份最多 10 MiB，单站附件上限 256 MiB。服务器核对扩展名及文件签名，下载需要会话权限并强制作为附件。文件格式检查不等于杀毒。对话和附件都保存在持久化 SQLite 中。

客服结束会话只变更状态；文字和附件保留在「已结束」。运营账号可在「在线客服 → 会话记录」按站点、状态或会话编号查阅，停用的站点也可查看历史。查阅正文、下载附件均写入操作记录。正式站点应在隐私说明中明确运营查阅权限和保存期限。

## 告警处理

- 页面发送区有审核说明。首版规则只检查客服发出的文字；访客主动举报会另建告警。配置的 HTTP(S) 域名及其子域命中后会拒绝发送并记录告警。疑似索要凭证、诱导私下付款仅标记待复核。
- 运营账号可以在「在线客服 → 风险告警」查看事件，打开会记录审计日志。摘要会隐藏常见联系方式和数字串，仍可能含个人信息，请限制访问。复核人员可以确认风险或排除误报，填写理由。不会自动停用站点；管理员可根据复核结果手动停用。
- 「审核与通知」支持配置 OpenAI 兼容 API 地址、模型和 API Key。先保存并用虚构样例测试，再打开全局开关；单独在站点设置开启 AI 后才检查该站点。系统默认关闭，不补扫旧消息。内置允许 OpenAI、DeepSeek、DashScope 和硅基流动的 HTTPS 地址；自定义服务商需由维护者通过 `SUPPORT_AI_ALLOWED_HOSTS` 允许其主机名。改变服务商域名须重新填写 API Key。
- AI 异步检查新发客服文字。先遮盖常见号码、邮箱、链接、带标签的姓名和地址，以及可识别的账号和凭证格式，最多发送脱敏后的 1200 字符，不提供原文模式。不向模型提交访客消息、举报正文或附件。请在本站隐私说明中披露审核范围；风险告警由人工复核，AI 不拦截聊天。脱敏为规则识别，不能保证覆盖所有自然语言表达。
- 新举报和 AI 风险通知进入现有 SMTP 队列，发往「系统设置 → 邮件通知」的运营收件人。短时间内同站同类告警可以合在一封；邮件仅含站点和编号，详细内容留在后台。SMTP 暂不可用时保留待发记录，可在邮件通知中查看发送状态。
- 数据没有配置自动清理任务，上线前需约定保留期限与清理操作；30 天 Cookie 有效期不是数据库保存期限。

## 反向代理与上线

- 保留现有 `DATA_DIR`、授权签发私钥、管理员配置、数据库挂载和反代设置。应用启动仅新增 `support_*` 表及索引，原业务数据不需要导入、覆盖或重建。
- 保留实际 `Host`，HTTPS 环境使用 `COOKIE_SECURE=true`。如果已启用 `AUTHORITY_ALLOWED_ORIGINS` 白名单，务必把客服域名纳入；聊天写入还会核对当前请求的 Host，不能借另一个白名单域名跨源写入。代理上传大小至少允许 10 MiB。页面可见时增量轮询，断网后自动退避，恢复后刷新。
- 若使用独立客服域名，反代只放行对应的 `/chat/<站点编号>`、`/chat/<站点编号>/agent`、`/api/support/<站点编号>/…` 和 `/assets/…`；运营后台与 `/api/support-admin/…` 留在运营域名。需要按访客 IP 限流时，反代必须用真实来源覆盖 `X-Real-IP`，并在 `SUPPORT_TRUSTED_PROXY_IPS` 中配置应用实际看到的反代直连 IP，其他来源的转发头不可信。每次消息发送都有请求编号，弱网重试不会重复写入。
- 更新前确认正在运行的版本、SQLite 数据目录与挂载。保留旧镜像；先用 SQLite 的在线备份功能生成一致快照（或停服务后备份整个持久化目录），验证快照 `PRAGMA quick_check`，密钥和配置的备份保持私有权限。不要运行初始化脚本来替换已有配置。
- 先验证备份副本可启动，再切换服务。部署后先检查健康、原后台登录和已有客户/授权，再创建独立测试站点，跑两访客、客服收发、附件隔离及举报。出现回归时先切回旧镜像、保留数据目录；除非确认数据损坏，否则不要用旧快照覆盖上线后的新写入。

## 本地验证

`npm test` 覆盖旧数据保留、原接口回归、跨站点和会话隔离、附件验证、站点停用、凭证重置、举报与告警复核。构建后运行 `npm run test:browser:support`，用内存数据库验证运营开站、移动访客、客服回复、附件下载和告警处置。两个测试都不访问生产数据。

可用 `SUPPORT_E2E_PROFILE` 切换 `desktop`、`android-wechat`、`android-qq`、`ios-safari`、`ios-wechat`、`ios-qq` 和 `ios-small`。内置浏览器配置使用 Chromium/WebKit 与相应的视口、UA 模拟；真机仍需检查键盘、附件选择器和下载行为。
