# 沧烁授权运营中心

这是我们自己的运营后台，管理各客户的购买记录、功能定价、签名授权和客户端版本目录。

## 首版已实现

客户及实例登记；授权域名白名单；客户维护期管理；已接入模块的定价与上架；订单价格/期限快照；人工收款确认；授权签发与续期；重复领取幂等；授权到期与维护期一致；公钥交付；版本草稿/目录发布；操作记录。

账号采用 scrypt 密码哈希、服务端会话、HttpOnly/SameSite Cookie、CSRF 校验和登录次数限制。数据库采用独立 SQLite，签发使用 Ed25519。数据库绑定签发公钥指纹，发现签发身份变化会拒绝启动。不会保存客户服务器 root 密码或客户支付密钥。

## 本地运行

推荐 Node.js 24；最低 Node.js 22.13。22.x 的内置 SQLite 会提示实验性警告；只使用 `DatabaseSync` 的基础 API，CI 同时测试 22 与 24。

```powershell
$env:TEMP='D:\CodexData\temp\detla-authorize'
$env:TMP=$env:TEMP
$env:TMPDIR=$env:TEMP
$env:npm_config_cache='D:\CodexData\temp\detla-authorize\npm-cache'
npm ci

npm run build
npm start
```

首次初始化生成 `.env.local`（独立登录密码）及 `.local/license-private.pem`、`.local/license-public.pem`。密码与私钥不打印；初始化命令拒绝覆盖已有文件。登录账号默认 `admin`，请在本机查看 `.env.local` 中的密码。默认仅监听 `127.0.0.1:17441`。

开发时分别运行 `npm run dev:server`（17441）和 `npm run dev`（17440）；后者代理 API 到本地后端。

可通过 `DATA_DIR` 和 `AUTHORITY_ENV_FILE` 指定其他独立状态及配置目录。测试与构建时所有本机可控临时产物应放在 D 盘。

## 真实开通流程

1. 为客户系统配置客户编号及本中心导出的验证公钥。客户端最低版本为 `1.1.0-preview.2`。
2. 运营人员登记客户和客户后台显示的实例 UUID、客户端版本、授权域名及维护期。一个实例只属于一个客户；授权域名支持 `*.example.com` 子域名。
3. 为实际已实现的模块设置价格与期限，再上架。初始收益对比模块为未定价草稿，不会误售。
4. 创建购买订单，确认实际收款后填写核对凭据。后台只记账，不执行支付或扣款。
5. 签发授权，交付完整 JSON 给客户。客户在功能商城导入并启用。授权同时绑定客户、实例和域名；签发私钥留在本中心。
6. 续费通过新订单办理。授权和所有功能模块到期时间直接采用维护期结束时间；延长维护期后重新签发。重复签发同一个订单返回原授权，不重复延长维护期。签发内容包含该实例当前有效模块的完整集合、域名和到期时间。

客户侧仍校验客户编号、实例、签名和到期时间。已有基础功能不受扩展授权影响。离线文件无法即时撤销，也不能保证拥有 root/源码的客户无法修改校验；联网租约与撤销属于后续阶段。

## 版本发布的边界

这里发布的是版本目录及说明，指向客户端仓库的 GitHub Release；不会自动创建 GitHub Release、上传镜像、改客户数据库或安装程序。正式安装代理应在签名发布包、备份、迁移与回退验证完成后接入。

首版没有在线收款、订阅自动续费、退款自动撤销、多运营账号或客户自助安装。人工收款记录只用于已核对后的开通，不能当作第三方支付回调。

## 数据与密钥

数据库位于 `DATA_DIR/authority.sqlite`，启用 WAL。数据库、签发私钥及运行配置须独立保密并一致备份；不要只复制正在运行的单个 `.sqlite` 文件而遗漏 WAL，也不要删除数据库/更换密钥来重置密码。推荐停服务后备份整个状态目录和配置，保留原访问权限。

Git 忽略本地配置、私钥、数据库、授权文件及构建产物。公钥和一次性测试授权样本可以交给客户端集成测试；测试私钥不能与生产签发身份共用。

## Docker

镜像使用 Node.js 24。将状态目录挂载至 `/app/data`，以容器运行用户可读写的权限初始化；首次运行初始化命令生成 `/app/data/operator.env`，之后以该配置启动。反向代理需保留原始 Host，或配置 `AUTHORITY_ALLOWED_ORIGINS=https://实际授权域名`，并使用 HTTPS；线上设置 `COOKIE_SECURE=true`，Cookie 才会仅经 HTTPS 传输。不要直接将预览服务公开到互联网。

见 `deploy/compose.yml`。该配置默认仅绑定本机 17441；上线前检查实际端口和域名，不与客户服务复用端口。
